## 1. ГЛАВНОЕ ПРАВИЛО

С этого момента все изменения CHICHI SQUISH WAREHOUSE должны проходить обязательную проверку по утверждённым визуальным референсам.

Тебе предоставлены два основных изображения:

**REFERENCE A — CHICHI SQUISH WAREHOUSE**

Общий визуальный эталон помещения: стеклянный арочный потолок, золото, пастельный неон, гигантские сквиши, коллекционные витрины, яркие материалы и взаимодействующие котики.

**REFERENCE B — SQUISH PHYSICS: 5 ZONES**

Инструкция по пяти категориям и состояниям материалов:

1. Butter Squish Kingdom.
2. Slime Lab.
3. Jelly Squish Universe.
4. Cloud Squish Paradise.
5. Crunchy & Memory Foam.

REFERENCE A определяет архитектурный и художественный стиль.

REFERENCE B определяет внешний вид физических реакций на действия.

**НЕЛЬЗЯ СЧИТАТЬ ЗАДАЧУ ЗАВЕРШЁННОЙ ТОЛЬКО ПОТОМУ, ЧТО КОД УСПЕШНО СОБРАЛСЯ.**

Результат должен пройти сравнение с изображениями и реальную проверку поведения внутри игры.

## 2. СИСТЕМА REFERENCE-DRIVEN DEVELOPMENT

Создай единый рабочий цикл:

**REFERENCE → IMPLEMENTATION → SCREENSHOT → COMPARISON → CORRECTION → RETEST**

После каждого значимого изменения:

1. Запусти актуальную версию игры.
2. Открой соответствующую зону Warehouse.
3. Установи заданный ракурс камеры.
4. Переведи объект в тестируемое состояние.
5. Сделай реальный игровой скриншот.
6. Сравни его с соответствующей частью референса.
7. Выяви конкретные визуальные несоответствия.
8. Определи технические причины.
9. Исправь их.
10. Снова запусти тест.
11. Сделай новый скриншот.
12. Повтори проверку.

Не переходи к следующему этапу, пока критические ошибки текущего не устранены.

Если выполнение невозможно из-за отсутствия инструментов доступа к браузеру, не выдумывай результат. Настрой доступную автоматизацию или явно сообщи, что именно не удалось проверить.

# 4. ПЯТЬ ОБЯЗАТЕЛЬНЫХ ВИЗУАЛЬНЫХ ТЕСТОВ

## TEST 01 — BUTTER SQUISH KINGDOM

Референс показывает четыре состояния.

### STATE A — NORMAL

Сквиш целый.

Поверхность:

- Гладкая.
- Кремовая.
- Мягкая.
- С характерными золотистыми бликами.
- Без трещин.

Сделай скриншот до взаимодействия.

### STATE B — PRESS

Котик нажимает лапой.

На поверхности появляется локальная вмятина.

Материал растекается в стороны.

Сделай скриншот в момент максимального давления.

### STATE C — CRACKED

При достаточном воздействии поверхность покрывается трещинами.

Важно:

- Трещины начинаются в области напряжения.
- Имеют неодинаковые размеры.
- Не выглядят нарисованной поверх изображения сеткой.
- Следуют деформированной поверхности.

Сделай крупный скриншот трещин.

### STATE D — FRACTURED

При более сильном воздействии оболочка локально разрушается.

Появляются отдельные фрагменты.

Под ними видна мягкая сердцевина.

Сделай скриншот разрушенного состояния.

### Проверка

Не переходи дальше, если все четыре состояния выглядят почти одинаково.

Butter должен демонстрировать реальное различие между нажатием, появлением трещин и локальным разрушением.

---

## TEST 02 — SLIME LAB

Референс показывает четыре физических состояния.

### STATE A — REST

Слайм находится в спокойном состоянии.

Поверхность:

- Глянцевая.
- Полупрозрачная.
- Плавная.
- С красивыми фиолетовыми и бирюзовыми бликами.

### STATE B — STRETCH

Котик или игрок вытягивает слайм.

Проверь:

- Удлинение материала.
- Уменьшение толщины.
- Формирование длинных нитей.
- Отсутствие разрывов геометрии.

### STATE C — TWIST

Материал закручивается.

Должны появляться:

- Спиральная форма.
- Локальное натяжение.
- Перекрученные нити.
- Неравномерная толщина.

Не вращай весь слайм как один твёрдый предмет.

### STATE D — MERGE

Две небольшие массы слайма соединяются.

Поверхность постепенно становится непрерывной.

Не допускай заметного пересечения двух неизменных геометрических объектов вместо слияния.

### Проверка

Сними короткую видеопоследовательность:

REST → STRETCH → TWIST → RELEASE → MERGE.

Оцени не только отдельные кадры, но и плавность переходов.

---

## TEST 03 — JELLY SQUISH UNIVERSE

### STATE A — REST

Большой полупрозрачный розовый желейный кот.

Сохраняет правильный силуэт.

Уши и мордочка выглядят аккуратно.

### STATE B — IMPACT

Котик прыгает на желейного сквиша.

Поверхность прогибается под местом приземления.

### STATE C — WOBBLE

От точки контакта распространяются волны.

Соседние участки колеблются с небольшой задержкой.

### STATE D — RECOVERY

После прекращения нагрузки объект постепенно возвращается к исходной форме.

### Проверка

Запиши 3–5 секунд реального движения.

Не засчитывай тест, если объект просто равномерно уменьшается, затем увеличивается.

Требуется локальная деформация и объёмная волна.

---

## TEST 04 — CLOUD SQUISH PARADISE

### STATE A — REST

Огромное пушистое облако.

Поверхность мягкая, матовая, объёмная.

### STATE B — SINK

Котик ложится или садится.

Его лапы и тело постепенно погружаются в материал.

### STATE C — FULL COMPRESSION

Под котиком появляется широкая мягкая вмятина.

Соседние участки слегка поднимаются.

### STATE D — RECOVERY

Котик уходит.

Материал медленно возвращается к прежней форме.

### Проверка

Особенно внимательно проверь, чтобы котик:

- Не висел над поверхностью.
- Не проваливался сквозь геометрию.
- Правильно опирался лапами.
- Двигался синхронно с деформацией.

---

## TEST 05 — CRUNCHY & MEMORY FOAM

Эта часть референса показывает две разные физические технологии.

### CRUNCHY

Нажатие вызывает:

- Сжатие оболочки.
- Движение внутреннего наполнителя.
- Локальные неровности.
- Звуковой эффект хруста.

### MEMORY FOAM

После нажатия:

- Остаётся глубокий отпечаток.
- Его форма соответствует лапе.
- Он сохраняется некоторое время.
- Затем медленно исчезает.

### Проверка

Не смешивай эти физические реакции.

Crunchy должен реагировать через наполнитель и хрустящие элементы.

Memory Foam должен демонстрировать память формы.

- Ширину проходов.

- Количество и расположение декоративных элементов.
- Видимых котиков.
- Различимость тематических зон.

# 6. СТАНДАРТИЗАЦИЯ СКРИНШОТОВ

Чтобы сравнение было воспроизводимым, создай фиксированные камеры для тестирования.

Для каждой зоны сохраняй:

- Camera position.
- Camera target.
- Field of view или orthographic zoom.
- Aspect ratio.
- Resolution.
- Lighting state.
- Scene time.
- Object position.
- Test action.
- Test state.

Для повторных проверок используй те же параметры.

Не меняй ракурс между тестами только ради того, чтобы скрыть дефекты.

Создай три основных вида:

**CAMERA A — OVERVIEW**

Вся тематическая зона.

**CAMERA B — INTERACTION**

Котик и интерактивный объект целиком.

**CAMERA C — MATERIAL CLOSE-UP**

Крупный план конкретной деформации.

Для физического сравнения фиксируй ракурс и момент физического действия.

# 8. АВТОМАТИЧЕСКИЙ СБОР СКРИНШОТОВ

Если в проекте доступен Playwright или другая система браузерных тестов, используй её для автоматических снимков.

Типовой сценарий:

1. Открыть локальную игру.
2. Загрузить тестовое состояние.
3. Перейти в Warehouse.
4. Выбрать нужную комнату.
5. Установить зафиксированную камеру.
6. Установить фиксированное освещение.
7. Активировать нужное взаимодействие.
8. Дождаться заданного шага симуляции.
9. Сохранить скриншот.
10. Сохранить метаданные теста.

Для физики используй детерминированный тестовый сценарий:

- Фиксированный random seed.
- Фиксированный timestep.
- Фиксированная сила воздействия.
- Фиксированная точка контакта.
- Фиксированная длительность взаимодействия.

Это позволит сравнивать результаты разных версий игры.

Если физический движок не обеспечивает полную детерминированность, используй допустимые диапазоны поведения, а не побитовое сравнение кадров.

# 9. VISUAL COMPARISON ENGINE

Реализуй автоматизированную систему анализа полученных изображений.

Используй несколько уровней сравнения.

## LEVEL 1 — GEOMETRY

Проверяй:

- Силуэты.
- Границы объектов.
- Пропорции.
- Расположение крупных элементов.
- Размеры зон.
- Положение котиков.

## LEVEL 2 — COLOR

Проверяй:

- Основную палитру.
- Контраст.
- Баланс тёплого и холодного света.
- Насыщенность.
- Наличие неоновых акцентов.
- Материальные различия.

## LEVEL 3 — DETAIL

Проверяй:

- Складки.
- Трещины.
- Поверхность слайма.
- Блики.
- Прозрачность.
- Объём.
- Контактные тени.
- Декоративную плотность.

## LEVEL 4 — PHYSICS STATES

Проверяй:

- Глубину деформации.
- Положение контакта.
- Форму вытянутых нитей.
- Локализацию трещин.
- Восстановление формы.
- Колебания поверхности.

## LEVEL 5 — TEMPORAL CONTINUITY

Проверяй видео:

- Отсутствие рывков.
- Отсутствие телепортации геометрии.
- Естественность ускорения и затухания.
- Синхронизацию лап и материала.
- Сохранение объёма, где требуется.
- Плавность переходов.

# 10. МЕТРИКИ И АЛГОРИТМЫ

Для кадров, снятых с одинаковой игровой камеры, можно использовать:

- SSIM.
- LPIPS, если доступна совместимая реализация.
- Color histogram distance.
- Edge comparison.
- Silhouette overlap.
- Region-based image differences.

При наличии доступной модели визуальных эмбеддингов можно добавить семантическое сравнение.

Не устанавливай тяжёлые зависимости без проверки совместимости с проектом.

### ВАЖНО

Концепт-арт и реальная игровая сцена не имеют одинаковой геометрии и освещения.

Поэтому для концепт-артов не устанавливай обязательное требование пиксельного совпадения.

SSIM или LPIPS между ними не должны становиться единственным критерием успешности.

Используй концепт-арт для проверки:

- Художественного стиля.
- Композиции.
- Цветов.
- Характерных элементов.
- Физических состояний.

Для точного регрессионного сравнения используй реальные игровые скриншоты предыдущей принятой версии.

# 11. СИСТЕМА ОЦЕНКИ

После каждого этапа создавай отчёт.

Оцени по шкале от 0 до 100:

- Visual Style.
- Geometry.
- Materials.
- Lighting.
- Squish Detail.
- Physics Behavior.
- Cat Interaction.
- Reference Fidelity.
- Performance.

Значения — оценка соответствия конкретным критериям, а не объективная математическая мера красоты.

Для каждого критерия приложи доказательства.

### Правило допуска

Не устанавливай универсальный порог вроде 95% сходства с изображением, если он не подтверждён проверками.

Вместо этого разделяй ошибки:

**BLOCKER** — критическая проблема, из-за которой этап нельзя принять.

**MAJOR** — существенное расхождение с референсом.

**MINOR** — небольшая визуальная недоработка.

**ACCEPTED** — критерий выполнен.

BLOCKER должен быть исправлен до перехода дальше.

# 14. PHYSICS REFERENCE VALIDATION

Для каждого материала сохраняй не только изображения, но и данные физических измерений.

### Butter

- Глубина вмятины.
- Размер области контакта.
- Порог появления трещин.
- Количество активных повреждённых областей.
- Сохранённая пластическая деформация.

### Slime

- Длина растяжения.
- Минимальная толщина нити.
- Угол закручивания.
- Время восстановления.
- Успешность слияния двух масс.

### Jelly

- Максимальная деформация.
- Амплитуда волны.
- Частота колебаний.
- Время затухания.
- Остаточная деформация.

### Cloud

- Глубина погружения.
- Скорость сжатия.
- Скорость восстановления.
- Корректность контакта с телом котика.

### Memory Foam

- Глубина отпечатка.
- Время удержания.
- Скорость восстановления.
- Соответствие формы отпечатка месту воздействия.

### Crunchy

- Локальная деформация.
- Реакция наполнителя.
- Синхронизация звука.
- Стабильность внешней оболочки.

Сопоставляй эти параметры с визуальными состояниями на референсе.

Не придумывай точные физические значения из картинки: числовые допуски нужно установить экспериментально для выбранного игрового масштаба.

# 15. СИСТЕМА ITERATIVE CORRECTION

Если выявлено расхождение, создай запись:

`VISUAL_ISSUE`

Она должна содержать:

- Зону.
- Материал.
- Текущее состояние.
- Ожидаемое состояние.
- Скриншот.
- Ссылку на референс.
- Предполагаемую техническую причину.
- Предложенное исправление.
- Приоритет.
- Статус.

### Пример
