# Вода: общий стандарт всей карты

## Последнее требование пользователя

**Одна общая текстура волн и общее ядро воды на всей карте**: океан мозазавра,
горки, капибары и остальные водоёмы. Улучшение общего ядра должно применяться
везде. Глубина, течение, масштаб волн и реальные отражения окружения задаются
параметрами этой системы. Отдельные художественные реализации по локациям —
проблема, которую нужно устранить. Референс — присланная игровая вода
**Crimson Desert**: прозрачность, читаемое дно, движение поверхности, отражения
и блики у камней, плотный разнообразный подводный мир.

**Последнее дополнительное уточнение:** вода горок — ОЧЕНЬ РАННИЙ ПРОТОТИП,
а не достаточный художественный результат. Её можно использовать как исходник;
визуальное сравнение вести с референсом Crimson Desert. Не выдавать отсутствие
ошибок компиляции или старое одобрение за достижение нового стандарта.

## Четыре разные записи — не смешивать

Обновлено **2026-11-16** по прямому уточнению пользователя. Причина: прежняя
вода остаётся слишком ранним прототипом, выглядит по-разному в разных локациях,
а океан/дно отклонены по прозрачности, движению, плотности и материалу.

1. Горки — очень ранний прототип, не финальный художественный эталон.
2. d6fa805 — историческая техническая база: исходники, ресурсы и параметры.
3. Crimson Desert — новый целевой художественный ориентир всей карты.
4. Стабильная опубликованная сборка — отдельная запись с полным SHA и
   подтверждением live assets в [CURRENT](../CURRENT.md). Она не равна одобрению.

## Реальная цепочка d6fa805

Все имена в этом разделе относятся к полному историческому SHA выше.

- `water-shading.js`: `waterMaterial`, `advanceWater`, `applyUnderwaterLighting`.
  Surface ShaderMaterial transparent, depthWrite=false, DoubleSide,
  forceSinglePass=true, toneMapped=false. Сохраняются native blending/sorting,
  уровень воды, шесть ограниченных ripple slots и общий clock.
- `waterFieldTexture()` создаёт один **128×128 RGBA**: RG — slope, B — каустика,
  A — движущаяся микроструктура. Восемь на восемь центров, фиксированный
  sin(n*127.1+17.7)*43758.5453 hash; без Math.random. Repeat, trilinear mipmaps,
  NoColorSpace. Точный byte hash закреплён в fixture; новая процедурная картинка
  не становится технологией d6fa805 по сходству названия.
- `water-environment.js`: однократный аналитический octahedral fallback 128²,
  NoColorSpace. Это запасной sky/coast probe, не фотография и не runtime capture.
- `slide-water.js`: настоящие потоки вдоль 3D rider-route, все дорожки, outlet,
  контактная пена, кольца и баллистические капли, bounded impact buffers.
  Метры по длине/ширине канала, а не один тайл на всю карту.
- `slide-basin-optics.js`: одноразовая нормализация metre ShapeGeometry UV в
  [0,1], define SLIDE_CATCH_POOL, blue0x24b9ff, shore0x98eaff, opacity.78,
  настоящее освещённое дно и его волновая геометрия.
- `showcase-water-optics.js::polishShowcaseWater`: локальная композиция
  параметров/шейдера; реальные вызовы в `showcase-water-assets.js`.
  UV/normal basis и probe orientation учитывают положение самой постройки.
- `showcase-bottom-light.js::polishShowcaseBottom` композирует прежний
  onBeforeCompile и cache key после applyUnderwaterLighting, а не стирает его.
  Общие часы/уровень, два field sample, фильтрованная каустика, без scene-copy.
- `showcase-surface-details.js`, `showcase-surface-assets.js`: коалесцирующая
  подготовка карт тремя workers и shared ownership. Во время QA проверять,
  загружена ли основная карта/реальное отражение, а не принять fallback за неё.
- `showcase-water-probes.js`: сохранённый реальный offline capture по manifest;
  octahedral orientation учитывает modelMatrix[0].

### Точные параметры исторического showcase-профиля

- Амплитуды .035/.028 м; phaseA=.68*x+.44*z+.8*t,
  phaseB=.79*z-.23*x-.6*t. Wave gain=1+3*uFall+.5*step(.5,uFlowing).
  В приёмнике fade .78..1 радиуса с согласованным градиентом нормали.
- Slopes=(fieldA.rg-.5)*.065+(fieldB.gr-.5)*.115.
  Fresnel F0=.0204; roughness=sqrt(.005625+min(.04,|fwidth(slope)|²*.75));
  probe mip bias=.6+roughness*4; glint gain=.025*(.4+.6*fieldB.a).
  Направление солнца normalize(-14,35,20).
- Толщина потока .23 м; lake depth=1.19-.79*smoothstep(.55,1,edge),
  optical path делится на max(facing,.22). Alpha=
  clamp(1-exp(-opticalDepth*.34)+fresnel*.85+foam*.4,.10,.96).
  Flowing foam ограничена .34. Считать значения в **скомпонованном** shader:
  hooks заменяют исходный GLSL, один скопированный фрагмент результат не повторит.
- Параметры мелкой плёнки не переносить буквально на океан глубиной200м.
  Общий material должен иметь физически согласованные параметры глубины/течения.
  Общий wet-phase clock 1.33 сохраняет реальную gravity9.81 и отдельную ходьбу;
  reduced motion ставит optical clock в0, ripple age>3.5 очищается.

## Генераторы, реальные источники, цвет и каналы

`node scripts/build-water-garden-surfaces.mjs` — собственный детерминированный
генератор d6fa805, НЕ внешний фотоскан. Integer hash:
374761393/668265263/1274126177, фиксированные параметры кода, без random seed.
14 PNG: wood/stone/moss/leaf — color512², normal256², roughness128²;
lawn/sand — color. Color sRGB; normal RGB и отдельный roughness RGB — linear,
A=255. Это НЕ упаковка Terrain3D normal.RGB/roughness.A. Внешнюю CC0-лицензию
собственному генератору не приписывать; отдельная лицензия в нём не объявлена.
Хеши его реальных сохранённых PNG находятся в source-and-assets manifest.

`node scripts/bake-water-reflections.mjs` уже есть в d6fa805.
`scripts/showcase-probe-inputs.mjs` перечисляет настоящих производителей;
revision=hash имён+байтов. Генерируются реальные статические мини-биомы с
подготовленными картами и lights. Offline CubeCamera256² HalfFloat → pack256²
octahedral PNG. **В d6fa805 pack применяет ACES-подобную формулу**
c*(2.51*c+.03)/(c*(2.43*c+.59)+.14); runtime читает NoColorSpace.
Не считать этот PNG линейным HDR/4: поздняя океаническая цепочка устроена иначе.
При изменении producer во время capture скрипт должен остановиться.

**В d6fa805 отсутствуют** `water-sand.js`,
`scripts/bake-mosasaur-reflection.mjs`, `scripts/mosasaur-probe-inputs.mjs`.
Их нельзя описывать как исходные части исторического эталона.

Поздний Mosa baker захватывает реальный статический тропический берег,
подготовленные карты и grass, исключая воду. Linear radiance/4, NoColorSpace,
runtime gain4; fallback gain1. Входы — актуальный MOSA_PROBE_INPUTS, а не
случайная картинка. Не создавать тяжёлое отражение всей сцены каждый кадр.
Входы и output hash менять только после настоящего capture, не hash-only.

Поздние ocean PBR scans: Rock Face03, Coral Ground02, Coast Sand01 — Poly Haven
CC0. [Лицензия/назначение](../../assets/ocean-surfaces.md),
[URL/MD5/SHA256](../../../public/art/ocean-rock/sources.json),
`scripts/build-ocean-rock-surfaces.py`. Albedo sRGB; OpenGL normal RGB,
linear roughness A, без второго переворота G. Сейчас Sand имеет **только albedo**:
PBR нормали/шероховатость песка ещё не подключены. Пять карт занимают
11 518 457 download /44 739 236 mipmapped GPU bytes до будущих изменений.

## Текущая архитектура и миграция к одному ядру

В нынешнем draft сосуществуют общий waterMaterial, showcase string hooks и
mosasaur-water-optics/profile/field. Это инвентаризация, НЕ требуемая конечная
архитектура. Последнее указание требует общих field/core для всего мира.
Сначала составить список всех вызовов/обёрток/подводного света: capybara,
lagoon, бассейны, потоки, showcase, океан. Параметры среды отделять от общей
технологии. Не оставлять «исправленную одну локацию» как выполненную задачу.

Непринятый Mosa prototype: swells .50/.23/.10 м, общая граница.83м;
shore fade .2..3м, depth scale35м, scatter0x258daa*.60,
extinction(.045,.012,.005). Это параметры кандидата, не универсальные стандарты.
Проверять знак/масштаб глубины, поглощение, подводный fog, double tint,
прозрачность/сортировку и нормали на реальном виде. Синяя vertex paint дна
убрана в draft, но пользователь всё равно отклонил его пустоту/материал.

## Владение ресурсами и подтверждённый бюджет

Исторический основной water surface fragment: **2 field lookups+1 probe**.
Cascade early return не делает probe lookup. Это не лимит всех семплов всей
сцены: PBR/подводные материалы имеют другие карты. Без per-pool targets,
scene-copy, per-frame regeneration или полных matrix/vertex uploads.
Shared immutable карты/геометрия; bounded ripples и scalar clocks.
Custom sampler должен быть виден cooperative shader warmup до первого показа.
Hooks композировать; program cache key менять согласованно; disposer не
удаляет ресурс другого владельца. Не снижать mobile DPR, тени или native cats.

## Проверка нового общего этапа

Точные source/build/dirty overlay/assets/свет/часы/камера/DPR фиксировать по
[правилам доказательств](../evidence-and-recovery.md). Новый native d6 reference
содержит полный bundle и original/instrumented runner; старые PNG не v2.

После заморозки producers: настоящие bake горок+Mosa, Node22 build;
`check-water.mjs`, `check-slide-water.mjs`, `check-global-water.mjs`,
visibility control, full npm test/Wrangler dry run, actual native game/SQLite.
Для каждого кандидата вести ДВА параллельных сравнения: со стабильным
полным SHA — выявлять ухудшения при одинаковых условиях; с указанными
референсами — оценивать приближение к цели. Удачный A/B против прототипа не
означает достижение Crimson Desert. Общий shader проверить на ВСЕХ водоёмах: поверхность/берег/дно/
подводный режим, потоки/приёмники, capybara и остальные острова, день/ночь.
Основные lights нынешнего мира постоянны: header «полночь» не доказательство
причины затемнения. Реальные параметры света/тумана фиксировать отдельно.
Полные frame intervals, хвосты, длинные паузы и память — без параллельного
CPU/GPU нагружения. SwiftShader не физический телефон. Публиковать после
полного CI, server/save verification и actual live asset hashes.


## Телефон и Mac

Единый художественный уровень не означает одинаковую физику поверхности:
океану нужны соответствующие длина/амплитуда волн и глубина, бассейну —
меньшие возмущения, лотку — согласованный downhill flow и тонкая плёнка,
водопаду — течение/листы/контакт/прозрачность. Это параметры общего ядра.
Адаптировать плотность и исполнение эффектов под устройство, сохраняя DPR,
читаемость, анимацию и бюджет. Отдельно проверять телефон и Mac; Linux
SwiftShader не доказывает ни один из них. Не обещать FPS/сходство без измерений
и реального визуального сравнения. В CURRENT указывать непроверенные устройства.
